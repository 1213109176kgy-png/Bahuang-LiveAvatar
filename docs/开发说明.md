# 修改这套数字人系统

Windows 开发环境与运行步骤见 [源码开发](源码开发.md)。

系统的三个运行服务是独立的：

- Windows `llama-server.exe`：8090，OpenAI-compatible `/v1/chat/completions`。
- Windows 便携 Python `sources/LiveTalking/app.py`：8010，WebRTC 数字人及 `/humanaudio`。
- Windows 便携 Python `app/server.py`：7860，我们自己的页面、中文 ASR、Qwen3-TTS 和连接逻辑。

## 从哪里开始改

1. 人设和回答长度：`config/local.json`。
2. 对话记忆：`app/server.py` 中 `history`。当前只保留当前 WebSocket 的近期对话。
3. 语音识别：`transcribe()`。当前 small/int8/CPU，中文固定为 `zh`。
4. 声音合成：`synthesize()` 为整句测试接口，`stream_to_avatar()` 为分段发送。使用 faster-qwen3-tts 0.2.6 包装官方模型并捕获 CUDA Graph，默认 Vivian。
5. 数字人音频：`run_turn()` 里的 `/humanaudio`，发送16kHz单声道PCM WAV。
6. 麦克风与停顿检测：`app/static/client.js`，当前采用前端 RMS 阈值和 0.8 秒停顿。
7. 画质、动作及口型：`sources/LiveTalking/avatars/wav2lip_avatar.py`。

## 当前接口

`GET /api/status`：检查本地模型、数字人、语音模型就绪状态。

`POST /api/avatar/offer`：代理到 LiveTalking 的 `/offer`，得到 SDP 和 sessionid。

WebSocket `/api/chat`：

```json
{"type":"session","sessionid":"连接数字人返回的会话ID"}
{"type":"chat","text":"你好，介绍一下自己。"}
{"type":"chat","audio":"16kHz WAV 的 base64"}
{"type":"interrupt"}
{"type":"clear"}
```

后端返回 `phase`、`user`、`assistant`、`done` 或 `error`。
没有数字人会话时可回传 WAV，已有会话时把 WAV 交给 LiveTalking，浏览器只播放 WebRTC 的音轨，避免双重声音。

`POST /api/test/tts`：`{"text":"测试文字"}`，返回生成的 WAV，用于验收。
`POST /api/test/asr`：发送 WAV 二进制，返回文字，用于验收。

## 之后可以优化的顺序

1. 先记录真实物理麦克风、首音频延迟、口型帧率。
2. 当前已经分段合成音频；下一步可把大模型文字也按句送进队列，继续降低首音频延迟。
3. 把 RMS 停顿检测换成 Silero VAD，按实测环境调阈值。
4. 更换自有/获准使用的人物底片并重新预处理。
5. 要声音克隆时接入 Qwen3-TTS Base，而不是把参考录音硬塞给 CustomVoice。
6. 加直播弹幕队列、过滤、欢迎和礼物逻辑，最后接 OBS/直播伴侣。

不要把某一轮 Wav2Lip 推理 FPS 或纯文字大模型速度，当成整轮语音对话延迟。
源码可直接修改；大型模型和依赖不进 Git，下载与安装版本在 `setup/` 中记录。

## 桌面配置与打包

desktop/main.js 管理本窗口启动的进程；preload.js 只暴露服务控制、模型选择和日志。app/settings.py 校验配置并用Windows DPAPI保存密钥；config_api.py 管理目录、素材导入和后台任务。media_worker.py 调用官方人脸预处理生成Wav2Lip人物。

页面入口为app/static/workbench.html，配套workbench.css、workbench.js；client.js处理音视频和聊天。修改后重新打开程序；后端修改需重启服务。

使用setup/build_portable.py构建，参数--electron指定Electron运行环境目录，--zip生成压缩包。ZIP排除密钥、日志、个人上传素材、桌面浏览器缓存和WSL镜像。
